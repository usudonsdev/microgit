# 非エンジニア版デスクトップアプリ: 実装メモ(段階 1)

2026-11-24 着手。設計の正本は [non-engineer-drive-sharing-design.md](./non-engineer-drive-sharing-design.md)、ZIP 文書の扱いは [non-engineer-preflate-integration.md](./non-engineer-preflate-integration.md)。コードは `desktop/engine/`(Rust)。

利用者から「要件にある機能をすべて実装し、レビューまで終える」よう依頼された(2026-11-24 2:30〜8:00、自律作業)。この文書は、作業の途中で中断しても後続が再開できるよう、決めたことと進捗を書く。

## 1. この実装で決めたこと(実装者の判断。利用者の確認待ち)

- **画面は、常駐するエンジンが 127.0.0.1 で開く小さなウェブページにする。** 右クリックの「過去のバージョンを確認」は `vereve-desk.exe show <ファイル>` を起動し、既定のブラウザで版の画面を開く。
  - 理由: 画面の技術が未決(preflate メモ §7)で、ブラウザなら Windows にも Linux にも追加の部品が要らない。この開発環境(Linux)で Playwright を使って画面を試験できる。後で Tauri などに移すときも、同じ HTML と API を使い回せる。
  - 安全: 127.0.0.1 だけで待ち受け、起動ごとの乱数の合言葉(トークン)が無い要求は断る。他のサイトのページから操作されないよう、書き込みの API は POST とトークンを必須にする。
- **エンジンと画面は 1 つの exe にまとめる**(preflate メモ §3 の推す形は「エンジンを別プロセス」だったが、画面がブラウザになったので、ブラウザとエンジンはもともと別プロセスである。ブラウザが落ちてもエンジンは残る)。
- **履歴の記録は、ファイルごとの版の記録にする**(設計メモ §3 の「フォルダの木のスナップショット」ではなく)。画面がファイル単位(右クリック)なので、ファイルごとの方が単純で、Publish・Fetch もファイルごとに独立して進められる。名前の変更の追跡は段階 1 では扱わない(別のファイルとして扱う)。
- **右クリックの項目は、従来のメニュー(`HKCU\Software\Classes\*\shell`)に足す。** 管理者権限が要らない。共有フォルダの中のファイルにだけ出すため、`AppliesTo` で場所を絞る。Windows 11 の最初の短いメニューに出すこと(パッケージの身元が要る)は、段階 1 では行わない。

## 3. 確かめたこと

- 結合試験 16 件(`desktop/engine/tests/flow.rs`): 記録と重複の省略、無視するファイル、重ねる復元、別のファイルの版を拒む、Office の分割とバイト一致の復元(自作の xlsx・docx)、2 台の Publish/Fetch、未着のチャンクの保留、一時名・競合コピー・偽の記録・壊れたチャンク、別のチームの拒否、分岐の表示、Publish 済みを書き換えない、再起動後の連番、同時に設定した 2 人が 1 つのチームになる、本文が先に届いたときの写し。すべて通る。
- 画面の試験(Playwright、手元の Linux): 2 台を常駐させ、設定 → xlsx を 3 回保存 → 版の画面 → 最古の版に戻す(セルの値が戻ることを確認)→ チームに共有 → もう 1 台の版の画面に、佐藤さんの 4 つの版が出る。合言葉の無い要求と、Host が違う要求は 403。
- Windows 向けに `x86_64-pc-windows-gnu` でクロスビルドできる(exe 約 3 MB)。**Windows の実機では動かしていない。**
- 書き出しのファイル名は、この環境の headless Chromium では常に「download」になった。Python の簡単なサーバーでも同じだったので、ブラウザの側の事情と判断した(普通のブラウザで確認が要る)。

## 4. レビュー(2026-11-24、別のエージェントによる独立レビュー)と対応

| # | 指摘 | 対応 |
|---|---|---|
| 1 | 常駐が複数起動できる(右クリックで複数のファイルを選ぶと同時に起動)。連番の重複、`published_upto` の巻き戻り、出した記録の書き換えにつながる | OS のファイルの錠(`run.lock`)で 1 つだけにした。コマンドの `publish` も錠を取り、取れなければ画面を使うよう伝える。3 つ同時に起動して 1 つだけ残ることを確認 |
| 2 | 拡張子が日本語などのとき、ダウンロードのヘッダーを作れずに落ちる。他の端末から来たパスでヘッダーを書き換えられる | 予備の名前には英数字の拡張子だけを使い、ヘッダーの作成で落ちないようにした。`報告書第3.5版` で確認 |
| 3 | 起動時の全ファイルの確認が Fetch より先で、Drive が届けた他の人の本文を自分の保存として記録する | Fetch を先にした |
| 4 | 「いまの内容」を一覧の最後で決めていて、時計のずれや、他の人の版と同じ中身に戻したときに、戻せない版ができる | ディスクのファイルの中身で決めるようにした。他の人の版と同じ中身でも、最新の版と違えば自分の保存として記録する |
| 5 | 読めない記録が 1 つあると、分割も Publish も止まり続ける | その記録だけ飛ばし、覚えておいて毎回読み直さない |
| 6 | 分割の途中で、写しとして消した記録を書き戻す | 書き戻す前に、記録がまだあるかを確かめる |
| 7 | Publish と、分割・取り込みの写しの削除が食い違う | Publish・Fetch・分割を 1 つの錠で順番に行う |
| 8 | 共有フォルダに壊れたチャンクが残っていても書き直さず、他の人が永久に保留になる | 既にあるチャンクも中身を確かめ、壊れていれば書き直す |
| 9 | 他の端末の記録のパスが、履歴フォルダや `C:` などを指せる | 取り込む前に、無視するパス・`:`・制御文字・`..` を拒む(`util::is_safe_rel`) |
| 10 | Windows で、消したファイルを戻せない(`\\?\` の前置きと、大文字・小文字) | 親フォルダで正規化し、前置きを外し、Windows では大文字・小文字を区別せずに比べる。**Windows 実機で未確認** |
| 他 | docx の中の部品が巨大(ZIP 爆弾)だと、分割でメモリを使い切る。起動時の全ファイルの確認が、オンライン専用のファイルを全部ダウンロードさせる | 未対応(次の段階)。preflate の上限(既定 128 MB)はかかっている |
