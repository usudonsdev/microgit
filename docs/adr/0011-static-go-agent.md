# ADR-0011: ゲストの agent は Go の静的バイナリで、init を兼ねる

| 項目 | 内容 |
|---|---|
| 状態 | 採用（初期設計書 §9 の ADR 候補 5 を、実装の結果とともに記録） |
| 日付 | 2026-09-26 |
| 決めた人 | 利用者（要件定義書 AD-5、#13 で Go に決定）。init を兼ねる判断と Go の版の固定は Claude（#15） |
| 関係 | 要件定義書 AD-5・AD-7・NFR-3、[guest-phase1.md](../guest-phase1.md) §2.1・§2.2、[ADR-0008](./0008-linux-native.md) |

## 決定

- agent は Go で書き、`CGO_ENABLED=0` の静的バイナリにする（外部ライブラリ無し、標準ライブラリだけ）
- ゲストでは initramfs の `/init`（PID 1）として動き、`/proc`・`/sys`・`/dev`・`/run` の mount も自分でする（init と agent を 1 つにした）
- 同じバイナリを、Linux ホストでは `unshare -Urm` で起動する（PID 1 でなければ stdin/stdout で命令を受ける）
- ビルドに使う Go は 1.27.1 に固定する（`guest/kernel/version.env`）

## 理由

| 観点 | 結果 |
|---|---|
| 大きさ | agent 3.0 MB 前後（Go 1.27.1、x86_64 3,059,836 / arm64 2,949,244 バイト）。Node.js をゲストに入れると本体だけで数十 MB になる |
| ゲストの中身 | カーネルと agent の 2 つだけ。シェルを入れない（AD-7） |
| 経路の共通化 | Linux の VM なしも、仮想マシンの中も、同じバイナリ・同じ命令 |
| 再現性 | `-trimpath -ldflags "-s -w -buildid="` と Go の版の固定で、2 回のビルドが 1 バイトも違わない（#15） |

## 採らなかった案

- シェル（busybox）：本体は約 1 MB と小さいが、`mount` などのコマンド群と、命令の受け答えの仕組みが別に要り、AD-7「シェルを入れない」に反する
- Rust：もっと小さくできる見込みだが、学習のコストが高い
- init と agent を分ける：PID 1 の仕事は mount 4 つだけで、分ける利点が無い

## 引き受けること

- PID 1 が終わるとカーネルが止まるので、agent は `main` から戻らない。困ったら電源を切る
- Go の版を上げると agent の大きさとバイト列が変わる（1.24 系から 1.27.1 で約 0.65 MB 増えた）
