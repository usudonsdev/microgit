# ADR-0009: ゲストは信用せず、検査はホストの Boundary Guard に集める

## 決定

- ゲストの中には検査の仕組みを置かない。agent は小さく正しく動くことに専念する
- ゲストから受け取った一覧と中身は、ワークスペースに書く前に、ホストの Boundary Guard（`src/boundaryGuard.ts`）で必ず検証する。ゲストがワークスペースに直接書く経路は無い
- マイクロ履歴の正本（shadow の Git）はホストにあり、ゲストの層はキャッシュ（ADR-0001）

## 理由

- 乗っ取られたゲストの中の検査は、検査ごと書き換えられる
- 正本がホストにあるので、ゲストで何が起きても「捨てて作り直す」を選べる

## 実装で決めた規則（要約）

パスの形、`.git` への書き込みの禁止（大文字小文字・末尾のドット・8.3 の短い名前・macOS が無視する文字を含む）、MicroGit の作業フォルダ、種類（ファイルとディレクトリだけ）、Windows で表せない名前、大文字小文字と Unicode の正規化のぶつかり（O-14：弾いて知らせる）、中身の sha256、リンクでの脱出、消してよいものの範囲、中身を全部受け取るまでワークスペースに触らない順番。全体は boundary-guard.md。

## 確かめ方

単体テスト 21 件（`boundaryGuard.test.ts`）、差分テスト（`kernel-backend-e2e.mjs`）、実際の VS Code の中のテスト（`overlayBackend.test.ts`）。
