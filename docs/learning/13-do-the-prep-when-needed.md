## 1. 何のための仕組みか

Node.js 版（カーネル版が使えない環境で動く Overlay）は、過去に戻るのを速くするために「その時点の完全なフォルダ（ビュー）」をディスクに作っておく。5.0.0 の途中まで、このビューを **保存のたびに** 作り直していた。

| 手元の Windows、Node.js 版 | 保存のたびの作り直し |
|---|---|
| 保存 1〜20 回目 | 512.3 ms |
| 保存 21〜40 回目 | **1,190.2 ms**（履歴とともに伸びる） |

利用者が保存するたびに 1 秒以上、次の保存を待たせていた。しかも、作ったビューのほとんどは使われない（過去に戻るのは、保存の回数よりずっと少ない）。

---

## 2. 仕組み

### 2.1 先回り（eager）と、使うとき（lazy）

| やり方 | いつ作るか | 費用を払う人 | 向いているとき |
|---|---|---|---|
| 先回り（eager） | 保存のたびに | 保存する人（毎回） | 作ったものをほぼ必ず使う |
| 使うとき（lazy） | 過去に戻るときに | 過去に戻る人（そのときだけ） | 作ったもののほとんどを使わない |

保存は何百回、過去に戻るのは数回。先回りで作ると、使わないものに何百回も費用を払う。MicroGit の最優先は「保存のタイミングで最速」なので、ビューは過去に戻るときに作ることにした。

### 2.2 遅くなった側を、必ず測る

費用を保存から過去に戻る側へ移すと、過去に戻る操作が遅くなるかもしれない。だから **移した先も測る**。

| 手元の Windows、Node.js 版、保存 40 回 | 変更前 | 変更後 |
|---|---|---|
| 保存 1 回の処理全体（最後の 20 回） | 1,317.5 ms | **124.0 ms** |
| 過去に戻る操作（10 回の p50） | 1,854.7 ms | 1,766.6 ms |

過去に戻る操作は遅くならなかった。過去に戻るときのビューの作り方（`ensureExpandedView`）は、もともと「いちばん近い展開済みのビューから、必要な層だけ当てる」ようになっていたからだ。保存のたびに作っていたのは、実はほとんどが二度手間だった。

### 2.3 まだ残っている先回り

同じ考え方を当てはめると、もう 1 つ残っている。保存のときの層の書き出し（`exportCommitLayer`）の中の `expandViewAfterExport` が、**親のコミットのビューがあれば、そのフォルダを丸ごとコピーして新しいビューを作る**。

- 保存を続けているだけなら、親のビューが無いので動かない
- 一度過去に戻ると、その時点のビューができるので、その後の保存では毎回ビュー全体のコピーが走る（ファイル数に比例）

今回の計測（保存してから過去に戻る順）では表に出なかった。**計測の手順が、利用者の使い方の一部しか通っていなかった**。#43 で「過去に戻った後に保存を続ける」計測を足して確かめる。

### 2.4 測るときの落とし穴：遅いと、テストそのものが壊れる

変更前のコードで保存 100 回を計ると、計測が 3 分かかり、2 回とも途中で「Document has been closed」で止まった。VS Code は、しばらく使われていない文書を閉じる。遅い処理を計ろうとすると、その遅さのせいで計測が最後まで行かないことがある。保存の回数を 40 回に減らして、変更前と変更後を同じ条件でそろえた。

## 3. 結果（CI、公開版と同じ形、保存 100 回の最後の 20 回の p50、run 36809764061）

| 環境 | 層 | 保存 1 回の処理全体（#41 の前 → 後） | 過去に戻る操作 |
|---|---|---|---|
| Ubuntu 24.04 | Node.js 版 | 512.0 → **17.6 ms** | 302.2 ms |
| macOS | Node.js 版 | 666.6 → **44.8 ms** | 1,144.3 ms |

Node.js 版の過去に戻る操作そのものは、もともと遅く、履歴とともに伸びる（手元の Windows で 40 回 1.8 秒、100 回 3.3 秒）。これは #43 で扱う。

## 4. このリポジトリではどこにあるか

| やっていること | 場所 |
|---|---|
| 保存のときに作り直さない | `src/extension.ts` の保存の処理（`result === 'rewound'` のときだけ `applyOverlayCheckout`） |
| 過去に戻るときにビューを作る | `src/overlay.ts` の `ensureExpandedView`（いちばん近い展開済みのビュー＋層） |
| まだ残っている保存のときのコピー | `src/overlay.ts` の `expandViewAfterExport`（#43） |
| 過去に戻る操作の時間も計る | `src/test/suite/overlayBackend.test.ts`（`MICROGIT_TEST_SAVE_BENCH` の `travels`） |

## 5. 手を動かして確かめる

1. 設定 `microgit.overlayBackend` を `nodejs` にして何回か保存し、`MicroGit: Overlay Status` の `save:` の `overlay` が 0 に近いことを見る
2. 過去に戻ってから保存を続け、`layer` の時間が増えるかを見る（§2.3）
3. `.microgit_overlay/views/` の下に、いくつビューができているかを数える
