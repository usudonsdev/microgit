## 1. 何のための仕組みか

14 回で、保存 1 回の「ディスクへの確定待ち」はジャーナルへの 1 回になりました。それでも Windows では、Git の形式のファイル（中身・フォルダの一覧・コミット・ブランチ・タグ・その履歴・index）を作るだけで、保存 1 回に約 0.017 秒かかっていました。記録の時間の 7 割です。

ジャーナルには、保存 1 回で書くものが全部入っています。停電しても、ジャーナルから Git のファイルを作り直せます（14 回）。つまり、**Git のファイルを保存のたびにすぐ書く必要は、もう無い** のです。

---

## 2. 仕組み

### 2.1 あとで書く（書き出しの遅延）

```
保存のとき
  ジャーナルに 1 つの記録として書き、確定を 1 回待つ   ← 待つのはここだけ
  Git の形式のファイルは書かず、メモリに貯める

保存が 0.3 秒落ち着いたとき
  貯めた分をまとめて書き出し（materialize）、ディスクに確定させ、ジャーナルを消す
```

まとめて書くと、得をすることがもう 1 つあります。保存を 10 回したあとに書き出すなら、ブランチのファイルは **最後の値を 1 回書くだけ** で済みます（ブランチの履歴＝reflog には 10 行を順に足すので、Git で 1 回ずつ更新したときと同じになります）。

データベースやファイルシステムが使う「書き込みをまとめる（write-back、遅延書き込み）」と同じ考え方です。

### 2.2 読む前には必ず書く（関所）

あとで書くと、新しい問題が出ます。**まだ書いていないものを、誰かが読もうとしたら？**

MicroGit の中には、隠しリポジトリを Git のコマンドで読む処理がたくさんあります（履歴のグラフ、過去に戻る操作、ほかの端末との同期など）。Git は、メモリに貯めているものを知りません。読む前に書き出していないと、最後の数回分が無い履歴を見てしまいます。

そこで、隠しリポジトリを読む処理の **直前すべてに「関所」** を置きました。

```ts
// src/extension.ts（runGit）
function runGit(cwd: string, args: string[], ...): string {
    flushPendingGitWrites(cwd);    // 関所：この場所に関係する、貯めている分を書き出させる
    return execFileSync('git', [...]);
}
```

関所は、貯めているものが無ければ何もしないので、気にせず置けます。ふつうのリポジトリ（利用者の作業フォルダ）への Git の呼び出しでは、隠しリポジトリの分を書き出しません（`target` で見分ける）。

### 2.3 毎回通る道には、関所を置かない

関所を置けば正しくなりますが、**保存のたびに通る道** に関所があると、保存のたびに書き出すことになり、遅らせた意味がなくなります。

MicroGit では、保存のたびに「HEAD に付いているタグ」をファイルから読んでいました。ここは関所を置かず、貯めているあいだは **記録の部品がメモリに持っている答え** を返すようにしました（`headTagFromMemory`）。

同じ理由で、「同じ中身に戻した保存」の次の記録で、戻った先のコミットの中身を Git に読ませていたところも、最近作ったコミットの中身をメモリに覚えておくようにしました。Git を起動すると、その前に関所が書き出しを始めるからです。

「関所を置く」と「そもそも読まない（メモリから答える）」を使い分けるのがコツです。

### 2.4 書き出すまでの間に、ほかの人が書き換えたら

書き出すまでの 0.3 秒の間に、ほかの処理（利用者が手で動かした Git など）がブランチを書き換えることもありえます。そのときは、書き出しのときに「最初の更新の前の値」と今の値を比べ、違っていたら **ほかの処理の書き換えを残します**。すぐに書いていた頃も「あとから書いた方が残る」結果だったので、それと同じにしました。

---

## 3. 結果

普通の Git と停電対策の設定をそろえて、保存 1 回の記録を比べました（手元の Windows、ファイル 200 個、保存 300 回、真ん中の値）。

| | 時間 |
|---|---|
| 普通の Git（`git add` → `git commit`） | 0.090 秒 |
| MicroGit 5.0.0（ジャーナルまで） | 0.025 秒（別の日の計測。その日の Git は 0.107 秒） |
| **MicroGit（#49 の後）** | **0.010 秒** |

引き換えに、保存が 0.3 秒の間もあけずに 64 回続くと、64 回目だけ書き出しの分（約 0.4 秒）長くなります。

| 場所 | 役目 |
|---|---|
| `src/fastMicroCommit.ts` の `applyTxn`・`stash` | ジャーナルに書いたあと、Git の形式のファイルを貯める |

## 6. もっと知りたいとき

- **write-back キャッシュ**：OS のページキャッシュ（書いたデータをメモリに貯め、あとでディスクに書く）。Linux の `dirty_writeback_centisecs` などの設定
- **読む前に書く（read-your-writes）**：分散システムの一貫性の用語。自分が書いたものは、自分が読むときには必ず見える、という約束
- **Git 自身の遅延**：`git gc --auto` や `core.fsyncMethod=batch` も、「あとでまとめて」の工夫
