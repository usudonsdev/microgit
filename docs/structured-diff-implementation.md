# 構造を理解した差分：実装（第 1〜3 段階）

2026-11-23〜24 実装（未公開）。構想は [structured-diff.md](./structured-diff.md)、第 0 段階（VS Code の外の保存の記録）は [external-saves.md](./external-saves.md)。

## 1. 使い方

- サイドバーの履歴の各行の「差分」ボタン、サイドバーの「差分を見る」、またはコマンド `verEve: Show Structured Diff`（`vereve.showStructuredDiff`）。
- 比べるのは、選んだ保存（マイクロ履歴のコミット）と 1 つ前の保存（最初の親）の、そのファイルの中身。どちらも shadow の Git の blob（正本のバイト列そのもの）。
- テキストは VS Code の差分エディタで開く（`vereve-blob:` の仮想文書）。それ以外は差分のパネル（`diffView.ts`）に出す。
- 設定：`vereve.diff.ffmpegPath`（空なら PATH から探す）、`vereve.diff.timeoutSeconds`（既定 120）。

## 2. 構成

| ファイル | 役割 |
|---|---|
| `src/diff/types.ts` | 結果の型（表・文書・スライド・画像・動画・テキスト・バイナリ・エラー）、ドライバの型、上限 `DiffLimits` |
| `src/diff/registry.ts` | ドライバの一覧と選び方（拡張子と先頭のバイト） |
| `src/diff/zip.ts`・`xml.ts` | 読むだけの ZIP と XML（依存を増やさないため自前。上限つき、独自の実体を展開しない、再帰しない） |
| `src/diff/seq.ts` | 列の対応づけ（Myers の差分、削除と追加の組み合わせ、語・文字の単位の差分） |
| `src/diff/table.ts` | 表どうしの差分（行・列の対応づけ、式の参照の移し替え）。xlsx と CSV が使う |
| `src/diff/xlsx.ts`・`csv.ts`・`docx.ts`・`pptx.ts`・`image.ts`・`png.ts`・`video.ts`・`text.ts` | 形式ごとのドライバ |
| `src/diff/worker.ts`・`runner.ts` | 別プロセスでの計算、時間の上限、取り消し、キャッシュ（`.microgit/diff-cache/`、300 件まで） |
| `src/diffCommand.ts`・`src/diffView.ts` | コマンド、保存とファイルの選択、パネルの描画 |

## 3. 形式ごとに何を出すか

| 形式 | 出すもの | 出さないもの（引き受けた制限） |
|---|---|---|
| xlsx・xlsm | シートの追加・削除・改名・並べ替え。行・列の挿入と削除。セルの値・式・**式の結果だけ**・書式（数値の書式・フォント・塗りつぶし・罫線・配置・保護のどれが変わったか）。結合セル。解釈しない部品（グラフ・ピボットなど）は「変わった」とだけ | 条件付き書式・入力規則・名前の定義・グラフの中身。日付の書式のセルも数値のまま出す |
| CSV・TSV | 行・列の追加と削除、セルの変更（文字コードは BOM・UTF-8・Shift_JIS を判定） | 値の型（すべて文字列として比べる） |
| docx | 段落の追加・削除・変更（語・文字の単位）、書式だけの変更、表のセル、見出し、ヘッダー・フッター・脚注・コメント | 表のセルの行・列の番号、図形の中身、変更履歴の作者 |
| pptx | スライドの追加・削除・並べ替え・変更、図形の文字の変更・追加・削除・移動、画像の差し替え、ノート | 図形の書式（色・線・文字の書式） |
| 画像 | 変わった矩形（最大 50）、変わった画素の割合、前・後・差を赤で重ねた縮小画像。大きさが変わったときは前後の画像だけ | PNG 以外は ffmpeg が要る。回転・拡大縮小の検出はしない |
| 動画 | 同じ・差し替え・追加・削除の区間（時刻とコマの番号）、区間ごとの前後のコマと差の画像、時間軸の帯、音声の変わった区間 | 「色を補正した」のような意味の言葉。ffmpeg が要る |

## 4. 決めたこと（structured-diff.md §7 の未決のうち、実装で決める必要があったもの）

利用者に「自律的に進めて」と任された（2026-11-24）ので、次のとおり決めた。どれも変えやすい形にしてある。

- **ffmpeg は同梱しない。利用者が入れたものを使う**（PATH か `vereve.diff.ffmpegPath`）。同梱はライセンス（構成しだいで GPL）とサイズ（数十 MB、OS ごと）の判断が要るため。無ければ「ffmpeg が要る」と結果に出す。PNG の画像は ffmpeg なしで比べる（`png.ts`）。
- **動画を記録の対象にするか**は第 0 段階のまま：外の保存の記録の上限 `vereve.externalSaves.maxFileSizeMb`（既定 100 MB）で決まる。エディタの保存には上限は無い（今までどおり）。
- **xlsx の最初の範囲**：値と式に加えて、書式（どの観点が変わったか）と結合セルまで。条件付き書式などは後回し。
- **対象の利用者**：VS Code 版に足した。非エンジニア版とは、差分のドライバ（`src/diff/`）を VS Code に依存しない形にしてあるので、そのまま使える。

## 5. 主な判断と理由

- **計算は見るときだけ、別プロセスで**（structured-diff.md §4）。保存の速さに影響しない。信頼できないファイルを読む部品なので、拡張機能ホストと分け、メモリの上限（`--max-old-space-size=2048`）と時間の上限を付けた。子プロセスは `ELECTRON_RUN_AS_NODE=1` で起動する（VS Code の中では `process.execPath` が Electron のため）。
- **キャッシュのキー**は（ドライバ、版、上限、ffmpeg の有無、旧の中身の sha256、新の中身の sha256）。パスは入れない（同じ中身なら同じ結果）。timeout と internal のエラーは書かない。
- **xlsx の行・列の対応づけ**は、「行を先」と「列を先」の両方を試して、同じと分かったセルが多いほうを使う。列を挿入すると全行の指紋が変わり、行を挿入すると全列の指紋が変わるので、どちらを先にすべきかは変更しだいのため。片方だけでは列の挿入をうまく見つけられなかった（テストで確かめた）。
- **式は、旧版の式の参照を新版の番地へ移してから比べる**。行を挿入すると Excel は参照を書き換え（`=A4` → `=A5`）、範囲の中への挿入では範囲を広げる（`SUM(D2:D4)` → `SUM(D2:D5)`）。どちらも利用者の変更ではないので、式の変更に数えず、値が変われば「式の結果だけ」にする。
- **書式は番号でなく中身で比べる**。styles.xml の番号は保存のたびに変わりうる。s の無いセルは既定の書式（0 番）として比べる。
- **シートの XML は DOM にしない**（正規表現で走査）。大きなシートでメモリを使い切らないため。ブック・共有文字列・書式は小さいので DOM にする。
- **動画の「同じコマ」は、指紋の差の平均と最大の両方で判定する**（`FRAME_MEAN_THRESHOLD` = 3、`FRAME_MAX_THRESHOLD` = 32、32×18 のグレー）。書き出し直しの揺れは平均で吸収し、字幕 1 行のような小さい変化は最大で拾うため。根拠の測定は `video.ts` の注記。
- **画像の画素の差の閾値**は 16（JPEG・WebP は 40）。書き出し直しの揺れを変更に数えないため。

## 6. 確かめたこと・未確認のこと

確かめたこと（この環境、Linux、ffmpeg あり）：

- 単体テスト 216 件が通る（レビューの回帰テスト 8 件を含む）。差分のテストは xlsx・CSV 22 件、docx・pptx 23 件、PNG・画像・動画 22 件、別プロセスの計算 4 件。
  - xlsx：値・式・結果だけ・書式の区別、共有文字列の振り直しは変更にしない、行・列の挿入・削除、シートの追加・削除・改名・並べ替え、共有の式、結合セル、ZIP 爆弾、セルの上限、変更の数の上限。
  - 動画：書き出し直し（crf 18 → 28）は unchanged、途中の 1 秒の切り取りはその時刻の削除、1 秒の図形の重ね書きはその時刻の差し替え。
  - 別プロセスの計算：2 回目はキャッシュ、壊れた入力は format のエラー、時間の上限で打ち切り。
- VS Code の中のテスト：外で保存した CSV の 2 つの保存のあいだの差分を、コマンドから計算して結果が返る（子プロセスが VS Code の中で動く）。

未確認：

- 実機の Excel・Word・PowerPoint・LibreOffice が保存したファイル（テストの見本はテストの中で組み立てた最小の形）。特に、Excel の共有の式・配列数式・テーブル（ListObject）、Word の変更履歴とフィールド。
- 差分のパネルは、Chromium（Playwright）で CSV と動画の実際の結果を描いて確かめた（スクリプトのエラーなし、セルの値 `<b>田中</b>` は HTML にならず文字のまま出る）。VS Code の Webview の中での見た目（テーマの色）は未確認。
- Windows・macOS での子プロセスの起動と ffmpeg の探し方。
- 大きいファイルの時間（10 万セルの xlsx、10 分の 1080p の動画）。

## 7. レビュー（2026-11-24）と対応

実装のあと、別のエージェントに独立のレビューを頼んだ（安全性・正しさ・資源の漏れ。指摘は実行して確かめたもの）。11 件（高 0、中 4、低 7）。#7 の一部を除いて直し、回帰テストを `src/test/unit/diffHardening.test.ts` に足した。

| # | 重さ | 指摘 | 対応 |
|---|---|---|---|
| 1 | 中 | 細工した入力で時間が 2 乗になる：xlsx の閉じていない `<row>`（正規表現の遅延一致が毎回末尾まで読む）、式の参照の書き換え（1 文字ごとに切り出しと後戻り）、XML の対応しない閉じタグ（毎回スタックをたどる）、pptx の図形の対応づけ（O(n²)） | xlsx は要素を 1 回ずつ取り出す走査（`scanElements`）に、式は語の並びの先頭だけ試して並びごと読み飛ばす形（sticky 正規表現）に、XML は開いている名前の数を持つ形に、pptx は鍵ごとの一覧に。相対の式の指紋はセルごとに覚える |
| 2 | 中 | 20000 列以上でセルの鍵（行 × 20000 + 列）がぶつかる | xlsx は Excel の上限（1,048,576 行・16,384 列）の外の番地を形式のエラーに、CSV は 16,384 列を超えたら上限のエラーに |
| 3 | 中 | 音声の復号にメモリの上限が無い（無音は小さく圧縮され、巨大な PCM に展開される。ヒープの外なので `--max-old-space-size` で止まらない） | `DiffLimits.maxMediaSeconds`（既定 4 時間）までしか復号しない |
| 4 | 中 | 拡張機能ホストが両方の版の blob を丸ごと読む（上限 2 GB） | 先に `git cat-file -s` で大きさを確かめ、1 つの版あたり 512 MB を超えたら「大きすぎて比べられない」と知らせる。一時ファイルへ流し込む形は未対応（下の残り） |
| 5 | 低〜中 | キャッシュの鍵が ffprobe の有無を見ていない。ffmpeg の一時的な失敗もキャッシュされる | 鍵にツールの場所を両方入れた。ツールを使うドライバ（画像・動画）のエラーはキャッシュしない |
| 6 | 低〜中 | 共有の式のずらしで、シート名の付いた参照をずらさない | ずらしではシート名の付いた参照もずらす（`allSheets`） |
| 7 | 低 | 列全体・行全体の参照（`B:B`）を書き換えない。シートの名前を変えると、旧の名前の付いた式が変更に見える | シートの名前の変更は直した（比べる前に旧の名前を新の名前に、対応づけの指紋では自分のシートの名前を外す）。**列全体・行全体の参照は未対応**（列を挿入すると、その式が「式の変更」に見える） |
| 8 | 低 | 実体の名前でプロトタイプを引く（`&constructor;`）。`__proto__` の属性が消える | 自分の持つ実体だけ引く。属性はプロトタイプの無いオブジェクトに |
| 9 | 低 | ffmpeg・ffprobe が入力の形式を推測し、既定のプロトコルを許す（細工した再生リストで別のファイルを読ませうる） | `-protocol_whitelist file` を付けた |
| 10 | 低 | worker を止めても ffmpeg が残る。Windows で一時フォルダを消せずに例外になりうる | worker は SIGTERM と切断で ffmpeg を止めてから終わる。頼む側は SIGTERM のあと 2 秒で SIGKILL。一時フォルダの削除は再試行し、失敗しても結果を返す |
| 11 | 低 | `vereve.diff.ffmpegPath` をワークスペースの設定で任意の実行ファイルに向けられる | `"scope": "machine"`（利用者の設定でだけ決められる）。既存の `vereve.kernel.qemuPath` にも同じ形があるが、今回は変えていない（別の変更で検討） |

確かめて問題がなかったもの（レビューの報告から）：Webview は textContent だけを使い、画像は `data:image/png;base64,` で始まるものだけ。ZIP の項目数・展開後の大きさの上限、PNG の画素数の事前の確認。Myers の差分（2 万件の乱数の比較）。シェルを使っていない。一時ファイルのパスは絶対パスで、拡張子は文字を絞っている。worker の結果は 1 回だけ返す。

残り：blob を一時ファイルへ流し込む形（#4 の根本）、列全体・行全体の参照（#7）、`qemuPath` の scope（#11）。
